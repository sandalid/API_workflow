## Declared contract

**Query params** (`GetListingsQueryDto`, `get-listings-query.dto.ts:72-231`): `page`, `limit` (max 50), `brandId`, `categoryId` (required if `subcategoryId` set), `subcategoryId` (required if `typeId` set), `typeId`, `sellerId`, `status` ('sold', requires `sellerId`), `sort` (best/newest/price_asc/price_desc/most_liked/trending), `q`, `condition`, `size`, `material`, `color`, `era`, `freeShipping`, `minPrice`, `maxPrice`, `attributes` (repeated `slug:value`).

**Headers**: optional `Authorization` bearer (via `OptionalJwtAuthGuard`) — identifies the viewer for self-dealing/hidden-seller exclusion only; guests allowed.

**Response** (`toListingListDto`, `listings.service.ts:308-356`): `{ data: ListingListItem[], page, limit, total }` where each item has `id, sellerId, title, description, brandId, categoryId, subcategoryId, typeId, condition, priceCents, originalPriceCents, shippingCents, size, color, material, era, stock, currency, images[], videoUrl, tags[], likeCount, commentCount, watchersCount, ratingAvg, reviewCount, status, listingStatus, minOfferPercent, createdAt, brand{id,name,slug}|null, category{id,name,slug,iconName}, seller{id,username,displayName,avatarUrl,rating,ratingCount,salesCount,followersCount,location,lastActiveAt}`.

**Errors**: 400 validation (class-validator, e.g. bad `status`/`sellerId` combo, malformed `attributes`); no auth-required error (guest allowed).

## Looks unused but keep (and why)

- **`excludeSellerId` / `excludeSellerIds`** — not client-supplied (not in the DTO at all); computed server-side from the JWT and `UsersService.getHiddenSellerIds` (`listings.controller.ts:57-59,208-209`). Not a candidate for B1/A1 — by design the client never sends these.
- **`sort=trending` / `sort='best'`** — `'best'` is a documented no-op outside `/listings/search` with the hybrid flag on (DTO comment `get-listings-query.dto.ts:21-26`); not a bug, just scoped to a sibling endpoint.
- **`brandId`/`categoryId`/`subcategoryId`/`typeId`/`condition`/`size`/`minPrice`/`maxPrice`** request params — all actively sent by `getListings`/`getListingsBySeller` call sites and consumed in `buildFilterWhere`. Confirmed live, not candidates.
- **`ListingsService.findMany` also called from `saved-searches.service.ts:150`** — a different HTTP route (`GET /saved-searches/:id/results`), so none of its filter params should be called "unused anywhere" on the basis of EP-035 alone; checked and excluded from findings.
